综合比较：

|  | **进程（multiprocessing）** | **线程（threading）** | **协程（asyncio）** |
| --- | --- | --- | --- |
| **优点** | 可利用多核CPU | 相较于进程更轻，占用资源少 | 内存开销最少，启动数量最多 |
| **缺点** | 占用资源多，数量少 | 1）多线程只能并发执行，不能利用多核CPU（GIL） 2）线程切换开销 | 支持多库有限（aiohttp），代码复杂 |
| **适用** | CPU密集型 | IO密集型，同时运行多任务数量要求不多 | IO密集型，有超多任务运行，有库支持 |

## threading

```python
import threading

def foo(url): pass

threads = []

for url in urls:
    t = threading.Thread(target=foo, args=(url,))
    threads.append(t)
    
for t in threads:
    t.start()  # 启动线程
    
for t in threads:
    t.join()  # 等待结束
```

### pool

线程池：新建线程需要分配资源，结束线程需要回收资源，利用线程池可以减少新建和回收的开销。适用于处理突发性大量请求/需要大量线程且单个任务时间短。

具有**防御功能**：能够避免系统因创建线程过多导致负荷过大。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

# map，简洁
with ThreadPoolExecutor() as pool:
    results = pool.map(foo, urls)

# future模式，更强大
with ThreadPoolExecutor() as pool:
    futures = [pool.submit(foo, url) for url in urls]
    
for future in futures:  # 都完了按顺序返回
    print(future.result())
    
for future in as_completed(futures):  # 哪个先结束就返回，顺序不定
    print(future.result())
```

## asyncio

```python
import asyncio

loop = asyncio.get_event_loop()  # 获取事件循环

# 定义协程
async def foo(url):
    result = await do(url)  # IO，必须支持异步IO特性

tasks = [loop.create_task(foo(url)) for url in urls]  # 创建task列表
loop.run_until_complete(asyncio.wait(tasks))  # 执行
```

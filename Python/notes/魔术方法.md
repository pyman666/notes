可以通过`dir`和`vars`函数查看类结构。

1）`dir`函数不带参数时，返回当前范围内的变量、方法和定义的类型列表；带参数时，返回参数的属性、方法列表。如果参数包含方法__dir__()，该方法将被调用。如果参数不包含__dir__()，该方法将最大限度地收集参数信息；

2）`vars`函数返回对象object的属性和属性值的字典对象。

# 类属性

- `cls.__name__`

类名，**实例无**此属性

- `cls.__qualname__`

类或函数的限定名称，即从模块的全局作用域到类的点分路径

- `cls.__dict__`

类的**各种方法**和**类属性**字典，只读，**不可直接修改**

- `cls.__doc__`

文档字符串

- `cls.__bases__`

所有父类构成的元组

- `cls.__subclasses__`

返回一个列表，包含类的直接子类，使用弱引用，防止出现在超类和子类之间出现循环引用。返回的列表中是内存中现存的类

- `cls.__mro__`

查看类当继承关系

- `cls.__module__`

类定义所在的模块

# 实例属性

- `self.__class__`

实例所属的类名

- `self.__dict__`

实例内部所有属性（**无方法**）组成的字典，**可直接修改**

# 变量

- `__slots__`

1）指定实例后期可以添加的属性，但是这个并不是它的初衷，其更多的是用来作为一个**内存优化**工具。

2）定义了`__slots__`后，就不再有`__dict__`。由于每次实例化一个类都要分配一个新的`__dict__`，因此存在空间的浪费，在属性固定且且需要生成数以千计的实例的情况下，可以使用`__slots__`来优化内存；

3）如果`__slots__`中的属性与类属性同名，则实例属性为**read-only**。

- `__metaclass__`

指明元类，也可在定义类的时候通过`metaclsss`参数指明，查找元类时先通过继承关系查找，若父类未指明，则通过当前模块即py文件的`__metaclass__`参数查找，若没有则找到`type`。

# 方法

### 创建

- `__new__(cls, *args, **kwargs)`

创建对象时给对象分配内存的方法，返回对象的引用，python解释器获得对象的引用后，将引用作为第一个参数传给__init__。没写时，默认调用`object.__new__`

- `__init__(self)`

只负责初始化

- `__del__`

del实例或实例被释放时（如程序跑完）触发，del对象时删除的是“引用”，所以当对象存在多个引用时，仅在删除最后一个引用才会触发__del__

- `__prepare__`

元类中用于创建命名空间。prepare创建命名空间-> new创建类-> init初始化类

### 描述

- `__str__`

self本身的字符串描述，`print(ins/self)`、`str(ins/self)`可以得到这个字符串

- `__repr__`

1）`ins ↵` 时打印的东西，`repr(ins)`也可以得到；

2）如果 **str**() 没有被定义，那么就会使用 **repr**() 来代替输出；

3）生成的文本字符串标准做法是需要让 `eval(repr(x)) == x` 为真。如果实在不能这样子做，应该创建一个有用的文本表示，并使用 < 和 > 括起来；

4）`!r` 格式化代码（`'p is {0!r}'.format(p)`）指明输出使用 `__repr__()`来代替默认的 `__str__()`；

- `__format__`

自定义字符串的格式化，结合`format()`函数和字符串方法使用

### 类型

- `__iter__`

1）定义了就是**可迭代对象**`collections.abc.Iterable`；

2）若返回一个迭代器（如`iter`），就可以使用for循环；

3）若返回self，且定义类__next__方法，则变成一个生成器

- `__next__`

结合__iter__使self变成**迭代器**`collections.abc.Iterator`，可用`next`函数获取下一个值

- `__contains__`

实现了之后就是**容器**`collections.abc.Container`，可以用`in`判断。容器对象存储的仅仅是对象的**引用**，而不是对象本身

- `__call__`

实例直接调用即 `ins()` 时运行，为`collections.abc.Callable`

- `__bool__`

用于`if inst`判断布尔

### 属性

- `__setattr__`

1）`ins.attr = value` **都会调用这个方法**，在这个方法内部才会把属性存储到__dict__

2）可以用来屏蔽只读属性，但是只读属性还是可以通过 `ins.__dict__[attr] = value` 的方式修改；

3）这个方法内部不能通过`self.attr = value`，否则会死循环，可以配合__dict__使用

- `__getattr__`

如果属性查找在实例以及对应的类中（通过__dict__)失败， 那么会调用到类的__getattr__函数, 如果没有定义这个函数，那么抛出`AttributeError`异常。由此可见，__getattr__一定是作用于属性查找的最后一步，兜底

- `__delattr__`

只要采用del语句删除**类实例属性**时__delattr__就会被触发

- `__setitem__`

`ins[attr] = value`实例像字典一样赋值时调用，也能用于切片（`slice`类）

- `__getitem__`

实例像字典一样取值时调用，也能用于切片，`ins[attr]`，未定义__iter__也可以用于遍历

- `__delitem__`

实例像字典一样删值时调用，也能用于切片，`del ins[attr]`

- `__set__(self, ins, value)`
- `__get__(self, ins, owner)`
- `__delete__(self, ins)`

1）上述方法实现了一种就属于描述器；

2）假设描述器类D，类A中类属性d是D的实例，a是A的实例，则：`self`是d，`ins`是a，`owner`是A，`value`是对d赋值时传入的值；

- `__getattribute__`

定义实例属性查找顺序，如果为描述器实现，直接调用`__get__`方法，否则按照下文`__dict__`等顺序查找。一般不建议重载

### with

- `__enter__(self)`
- `__exit__(self, exc_type, exc_val, exc_tb)`

1）使对象支持**上下文管理协议**（`with`语句）；

2）当出现`with`语句的时候，对象的`enter`方法被触发，它返回的值（如果有）会被赋值给 `as` 声明的变量。然后，`with`语句块里面的代码开始执行。最后，`exit`方法被触发进行清理工作。不管 `with` 代码块中发生什么，上面的控制流都会执行完，就算代码块中**发生了异常也是一样的**；

3）`exit`中`self`外几个参数 _[异常类型，异常值，异常跟踪信息]_ ，有异常时赋值给他们，无异常时都为`None`，当调用类内函数有错的时候错误不能传递给`exit`的参数。若`exit`返回`True`/`1`，将忽略`with`内的异常，停止执行`with`内剩余语句，但是会继续执行`with`外的语句；如果函数返回`False`/`0`/`None`，将抛出 `with` 中的异常，那么在没有捕获异常的情况下，中断`with`内及`with`外的语句；

4）自包含的上下文管理函数也可以用`@contextlib.contextmanager`装饰器实现。 如果有一些对象（比如一个文件、网络连接或锁）需要支持`with`语句，需要单独实现`enter`和`exit`方法；

```python
class A:
    def __enter__(self):
        return self  # 返回值就是as后的值

    def __exit__(self, exc_type, exc_val, exc_tb):
        import traceback
        print(traceback.extract_tb(exc_tb))  # 没有return，return None，抛出异常
```

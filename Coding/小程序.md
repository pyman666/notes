## 代码构成

## 文件类型

每个页面由4个基本文件组成：

- `js`：页面脚本文件，存放页面数据、事件处理函数等；

- `json`：页面配置文件，配置窗口外观、表现等；

- `wxml`：（WeiXin Markup Language）页面模版结构文件，类似于html，区别：

  - 标签名称不同；

  - 属性节点不同；

  - 提供了类似于Vue中的模板语法；

- `wxss`：（WeiXin Style Sheets）页面样式表文件，类似于css，区别：

  - 新增了rpx尺寸单位；

  - 提供了全局样式和局部样式；

  - 仅支持部分css选择器；

## 文件目录

**根目录**

- `/pages`：存放所有页面，官方建议所有页面以单独的文件夹存放在`/pages`目录；

- `/utils`：存放工具性质的模块（如格式化时间的自定义模块）；

- `app.js`：项目入口文件，通过调用`App()`函数来启动整个小程序；

- `app.wxss`：项目全局样式文件，作用于所有页面；

- `app.json`：项目全局配置文件，包括所有页面路径、窗口外观、界面表现、底部tab等；

- `project.config.json`：项目配置文件，用来记录小程序开发工具所做的个性化设置；

- `sitemap.json`：配置小程序及其页面是否允许被微信索引；

**页面目录**

- `js`：页面入口文件，通过调用`Page()`函数来创建并运行页面；

- `json`：页面配置文件；

- `wxss`：仅对当前页面生效；

**其它目录**

- `js`：普通的功能模块文件，用来封装公共的函数或属性供页面使用；

# 宿主环境

宿主环境（host environment）指的是程序运行所必需的依赖环境。如Android和iOS是两个不同的宿主环境，安卓版的微信app是不能在ios环境运行的。

手机微信是小程序的宿主环境。小程序借助宿主环境提供的能力，可以完成微信扫码、微信支付、等功能。

小程序宿主环境包含的内容：

## **通信模型**

通信主体：渲染层、逻辑层，其中wxml、wxss工作在渲染层，js工作在逻辑层；

通信模型：渲染层🆚逻辑层、逻辑层🆚服务器，都是由微信客户端进行转发；

## **运行机制**

启动过程：下载小程序代码包 → 解析app.json → 执行app.js → 渲染首页 → 启动完成；

渲染过程：加载页面json → 加载页面wxml和wxss → 执行页面js → 渲染完成；

## **组件**

官方把组件大致分为9类：

- **视图容器**

  - `<view`**`>`**：普通视图区域，块级元素，类似html的`<div`**`>`**；

  - `<scroll-view`**`>`**：可滚动时图区域，滚动div；

  - `<swiper`**`>`**、`<swiper-item`**`>`**：轮播图容器、项；

- **基础内容**

  - `<text`**`>`**：文本组件，行内元素，类似html的`<span`**`>`**。通过`selectable`属性支持**长按选中**效果；

  - `<rich-text`**`>`**：富文本组件，可通过`nodes`属性节点把html字符串渲染为wxml结构；

  - `<button`**`>`**：按钮组件，类似html的`<button`**`>`**，功能更丰富，通过`open-type`属性可调用微信提供的各种功能（客服、转发、获取用户授权等）；

  - `<image`**`>`**：图片组件，类似html的`<img`**`>`**，默认宽度约300px，高度约240px；

  - `<navigator`**`>`**：页面导航组件，类似html中的`<a`**`>`**链接；

- **表单组件**

- **导航组件**

- **媒体组件**

- **map地图组件**

- **canvas画布组件**

- **开放能力**

- **无障碍访问**

## **API**

官方大致把API分为3类：

- **事件监听API**：以on开头，用来建厅某些事件的触发。如`wx.onWindowResize`监听窗口尺寸变化的事件；

- **同步API**：以Sync结尾，同步API的结果可以通过函数返回值直接获取，如果出错抛异常。如`wx.setStorageSync`项本地存储中写入内容；

- **异步API**：类似jQuery中的`$ajax(options)`函数，需要通过success、fail、complete接收调用的结果。如`wx.request`发起网络请求，通过success回调函数接收数据；

# wxml

## 数据绑定

在data中定义数据（在页面js文件中把数据定义到data对象），在wxml中使用数据，把数据绑定到页面中渲染需使用Mustache语法（双大括号）；
```jsx
Page({
  data: {
    info: 'hello world',
    src: 'http://www.itheima.com/images/logo.png',
    num: Math.random() * 10
  }
})
```
```xml
<view>{{info}}</view>
<image src="{{src}}" mode="widthFix"></image>
<view>{{num >= 5 ? '大于等于5' : '小于5'}}</view>
```
## 事件绑定

**事件**是渲染层到逻辑层到通讯方式，通过事件可以将用户在渲染层产生的行为反馈到逻辑层进行处理。

**事件类型**

- `tap`：`bindtap`/`bind:tap`，点击事件，类似html中的`click`，以**冒泡**的方式向外扩散；

- `input`：`bindinput`/`bind:input`，文本框的输入事件；

- `change`：`bindchange`/`bind:chanege`，状态改变时触发；

**事件属性**

- `type`：事件类型；

- `target`：触发事件的组件的一些属性集合，触发事件的源头组件；

- `currentTarget`：当前组件的一些属性集合，当前事件所绑定的组件；

- `detail`：额外信息；

- `timeStamp`：页面打开到触发事件所经过的毫秒数；

- `touches`：触摸事件，当前停留在屏幕中的触摸点信息的数组；

- `changedTouches`：触摸事件，当前变化的触摸点信息的数组；
```xml
<button type="primary" bindtap="btnTapHandler">按钮</button>
<input type="warm" bindinput="inputHandler"></input>
```
```jsx
Page({
  btnTapHandler(e) {  // 按钮tap事件处理函数，通过形成event（一般简写成e）来接收
		console.log(e)  // 事件参数对象e
  },

  bindinput(e) {
    console.log(e.detail.value)  // e.detail.value是变化后文本框最新值
  }
})
```
通过`this.setData`方法给页面data中的数据重新赋值
```xml
<button type="warm" bindtap="changeCount">加一</button>
```
```jsx
Page({
  data: {
    count: 0
  },

  changeCount() {  // +1按钮点击事件处理函数
    this.setData(
      count: this.data.count + 1
    )
  }
})
```
**事件传参**

不能在绑定事件的同时为事件处理函数传参，只能通过`data-xxx`自定义属性传参，其中`xxx`是参数名，通过`event.target.dataset.xxx`获取到参数值。
```xml
<button type="warm" bindtap="btnTap2" data-info="{{2}}">加二</button>
```
```jsx
Page({
  data: {
    count: 0
  },

  btnTap2(e) {
    this.setData(
      count: this.data.count + e.target.dataset.info
    )
  }
})
```
## 条件渲染

通过`wx:if=”{{条件}}”`来判断是否需要渲染该代码块
```xml
<view wx:if="{{type === 1}}">男</view>
<view wx:elif="{{type === 2}}">女</view>
<view wx:else>保密</view>
```
通过`<block>`标签一次性控制多个组件的展示于隐藏，`<block>`并不是一个组件，只是一个包裹性质的容器，不会在页面渲染
```xml
<block wx:if="{{true}}">
	<view>1</view>
	<view>2</view>
</block>
```
也可以通过`hidden`属性控制元素的显示与隐藏
```xml
<view hidden="{{type == 1}}">条件为true隐藏，否则显示</view>
```
`wx:if`🆚`hidden`区别：

- `wx:if`以动态创建和移除元素的方式控制显示与隐藏；

- `hidden`以切换样式的方式（`display: none/block`）控制元素的显示与隐藏；

- 频繁切换时，建议使用`hidden`；控制条件复杂时，建议使用`wx:if`;

## 列表渲染
```xml
<view wx:for="{{array}}">
	索引：{{index}}, 项：{{item}}
</view>

<view wx:for="{{array}}" wx:for-index="idx" wx:for-item="its">
	索引：{{idx}}, 项：{{its}}
</view>
```
类似于Vue中的`:key`，小程序也建议为渲染出来的列表指定唯一的key（无须Mustache），提高渲染效率；
```jsx
data: {
  userList: [
    { id: 1, name: 'Jack' },
    { id: 2, name: 'Tom' }
  ]
}
```
```xml
<view wx:for={{userList}} wx:key="id">{{item.name}}</view>
```
# wxss

定义在`app.wxss`中的样式为全局样式，作用于每个页面；每个页面的`wxss`文件中的样式为局部样式，作用于当前页面；

- 当局部样式和全局样式冲突时，根据就近原则，局部样式会覆盖全局样式；

- 当局部样式权重大于等于全局样式权重时，才会覆盖全局样式；

## rpx

rpx（responsive pixel）是微信小程序独有的，用来解决屏幕适配的尺寸单位。小程序在不同屏幕运行时，会自动把rpx样式的单位换算成对应的像素单位来渲染，从而实现屏幕适配；

**原理**：所有设备的屏幕在宽度上等分为750份（即当前屏幕的总宽度为750rpx）

## 样式导入

通过`@import`外联样式表的相对路径，用`;`表示语句结束，可以导入外联的样式表；
```css
@import "/css/common.wxss";

.user {
  display: flex;
  flex-direction: column;
}
```
```xml
<view class="user">  </view>
```
# json

## 全局配置

根目录的`app.json`文件是小程序的全局配置，文件中的window节点可以全局不配置小程序中每个页面的窗口表现。

常用配置项：

### pages

记录当前小程序所有页面的存放路径；

- 在pages中新增页面的存放路径，开发工具就会自动创建对应的页面文件；

- 调整pages中页面路径顺序，即可修改项目首页，排在第一个的会作为首页进行渲染；
```jsx
"pages": [
  "pages/index/index",
  "pages/logs/logs"
]
```
### style

是否启用新版的组件样式，默认启用；
```jsx
"style": "v2"
```
### window

全局设置小程序窗口的外观；

- 主要是配置导航栏和背景区域，而不包括页面主体区域（wxml）；

- 以navigationBar开头的配置项都是配置导航栏的，background开头的配置项都是配置背景的，还有一些其它配置项；
```jsx
"window": {
  "navigationBarTitleText": "张小龙",  // 导航栏标题
  "navigationBarTextStyle": "white",  // 导航栏标题颜色，black/white，默认white
  "navigationBarBackgroundColor": "#2b4b6b",  // 导航栏背景，只支持16进制
  "backgroundTextStyle": "dark",  // 下拉刷新时loading样式，dark/light，默认dark
  "backgroundColor": "#efefef",  // 下拉刷新时的背景色，只支持16进制
  "enablePullDownRefresh": true,  // 开启全局下拉刷新，默认false
  "onReachBottomDistance": 100  // 下拉触底距离，单位为px
}
```
### tabBar

设置小程序底部的tabBar效果；

- 包括顶部tabBar和底部tabBar，渲染顶部tabBar时，不显示icon，只显示文本；

- tabBar中只能配置最少2个、最多5个tab页签；

- tabBar页面必须放在pages列表的顶部；

组成部分：
```jsx
"tabBar": {
  "list": [  // tab页签列表，必须
    {
      "pagePath": "pages/index/index",  // 页面路径，必须
      "text": "index"，  // tab上显示的文字，必须
      "iconPath": "/img/index.png",  // 未选中时icon图片路径
      "selectedIconPath": "/img/index_.png"  // 选中时icon图片路径
    },
    {
      "pagePath": "pages/index/test",
      "text": "test"
    }
  ],
  "position": "",  // bottom/top，默认bottom
  "borderStyle": "",  // black/white，默认black
  "color": "",
  "selectedColor": "",
  "backgroundColor": ""
}
```
## 页面配置

当某些页面想拥有特殊的窗口表现，可以使用页面的json文件。

- 当页面配置与全局配置冲突时，根据就近原则，最终效果以页面配置为准；

- 配置项与`app.json`中`window`配置项相同，会覆盖`window`标签中相同的配置项；
```jsx
{
  "navigationBarBackgroundColor": "#2b4b6b"
}
```
# 网络数据请求

小程序数据接口请求限制：

- 域名只支持`https`协议；

- 域名不能使用IP地址或`localhost`；

- 必须将域名添加到信任列表中；
```xml
<button bindtap="getInfo">请求百度</button>
```
```jsx
onLoad: function() {
  this.getInfo()  // 页面加载时调用getInfo
},

getInfo() {
	wx.request({
	  url: 'https://www.baidu.com',
	  method: 'GET',
	  data: {
	    name: 'Jack',
	    age: 22
	  },
	  success: (resp) => {
	    console.log(resp)
	  }
	})
}
```
# 页面导航

## 页面跳转

**声明式导航**：在页面声明一个`<navigator>`导航组件，通过点击组件实现页面跳转；
```xml
<!--导航到tabBar页面（url必须以/开头）-->
<navigator url='/pages/msg/msg' open-type='switchTab'>导航到msg页</navigator>

<!--导航到非tabBar页面（open-type默认navigate，可省略）-->
<navigator url='/pages/info/info' open-type='navigate'>导航到info页</navigator>

<!--后退导航（delta默认1，可省略）-->
<navigator open-type='navigateBack' delta='2'>后退2页</navigator>
```
**编程式导航**：调用小程序导航API，实现页面跳转；
```xml
<button bintap="gotoMsg">导航到msg页</button>
```
```jsx
// 导航到tabBar页面
gotoMsg() {
	wx.swithTab({
	  url: '/pages/msg/msg',  // 必须
	  success: function(){},  // 接口调用成功的回调函数
	  fail: function(){},  // 接口调用失败的回调函数
	  complete: function(){}  // 接口调用结束的回调函数
	})
}

// 导航到非tabBar页面
gotoMsg() {
	wx.navigateTo({
	  url: '/pages/msg/msg'  // 另三个回调函数，同上
	})
}

// 后退导航
gotoMsg() {
	wx.navigateBack({
	  delta: 1,  // 默认1，非必须。另三个回调函数，同上
	})
}
```
## 参数传递

**传递参数**：在路径后携带参数；
```xml
<navigator url='/pages/msg/msg?name=Jack&age=20'>导航到msg页</navigator>
```
```jsx
gotoMsg() {
	wx.navigateTo({
	  url: '/pages/msg/msg?name=Jack&age=20'
	})
}
```
**接收参数**：在`onLoad`事件中获取参数；
```jsx
data: {
  query: {}
}

onLoad: function(options) {
  this.setData({
    query: options  // options就是导航传递过来的参数对象
  })
}
```
# 页面事件

## 下拉刷新

下拉刷新是指通过手指在屏幕上下拉滑动操作，从而重新加载页面数据的行为；

- 通过全局或局部`json`文件，来设置设置是否开启下拉刷新、导航字体等设置；

- 在页面`js`文件中，通过`onPullDownRefresh()`函数监听当前页面下拉刷新事件；

- 下拉刷新后，loading效果不会自动消失，调用`wx.stopPullDownRefresh()`可以停止下来刷新。
```jsx
onPullDownRefresh: function() {
  console.log('触发下拉刷新')
  wx.stopPullDownRefresh()
}
```
## 上拉触底

指通过手指在屏幕上的上拉滑动操作，从而加载更多数据的行为。

- 在页面`js`文件中，通过`onReachBottom()`函数监听页面上拉触底事件；

- 在全局或页面`json`文件中，通过`onReachBottomDistance`属性配置上拉触底距离，默认50px；

- 通过`wx.showLoading()`和`wx.hideLoading()`来展示或隐藏触底效果；

- 需要对上拉触底进行截流处理；
```jsx
data: {
  colorList: [],
  isLoading: false  // 截流阀，false表示可以请求
}

getColors() {
  this.setData({
    isLoading: true
  })

	wx.showLoading({
    title: "数据加载中...",  // 提示内容，必填
    mask: false,  // 是否显示透明蒙层，防止触摸穿透
    success: function(){},  // 接口调用成功的回调函数
    fail: function(){},
    complete: function(){},  // 接口调用结束的回调函数（成功失败都会执行）
  })

  wx.request({
    url: "https://www.color.api",
    method: "GET",
    success: ({data: res}) => {
      this.setData({
        colorList: [...this.data.colorList, ...res.data]
      })
    }
    complete: () => {
      wx.hideLoading()
		  this.setData({
		    isLoading: false
		  })
    }
  })
}

onLoad: function(options) {
  if (this.data.isLoading) return
  this.getColors()
}

onReachBottom: function() {
  console.log('触发上拉触底')
  this.getColors()
}
```
```xml
<view wx:for="{{colorList}}" wx:key="index" class="num-item" style="background-color:rgba({{item}});">
{{item}}
</view>
```
```css
.num-item {
  border: 1rpx solid #efefef;
  border-radius: 8rpx;
  line-height: 200rpx;
  margin: 15rpx;
  text-align: center;
  text-shadow: 0rpx 0rpx 5rpx #fff;
  box-shadow: 1rpx 1rpx 6rpx #aaa;
}
```
# 生命周期

**应用生命周期**：小程序启动、运行、销毁的过程；**页面生命周期**：页面加载、渲染、销毁的过程；

应用生命周期函数需要在`app.js`中声明：
```jsx
App({
  onLaunch: function(options) {},  // 初始化完成时执行，全局只触发一次，可以做一些初始化工作
  onShow: function(options) {},  // 启动或从后台进入前台显示时触发
  onHide: function() {}  // 前台进入后台时触发
})
```
页面生命周期函数需要在页面的`js`文件中声明：
```jsx
Page({
  onLoad: function(options) {},  // 监听页面加载，一个页面只调用一次
  onReady: function() {},  // 监听页面初次渲染完成，一个页面只调用一次
  onShow: function() {},  // 监听页面显示
  onHide: function() {},  // 监听页面隐藏
  onUnLoad: function() {},  // 监听页面卸载，一个页面只调用一次
})
```
# wxs

WXS（WeiXin Script）是小程序独有的一套脚本语言，结合wxml，可以构建出页面的结构。

- wxml中无法调用在页面的js文件中定义的函数，但可以调用wxs中定义的函数;

- wxs典型应用是过滤器，常结合Mustache语法使用，不能作为组件的事件回调函数；

wxs类似于js，不同点：

- wxs有自己的数据类型（number、string、boolean、object、function、array、date、regexp）；

- wxs不支持类似于ES6及以上的语法形式（如不支持let、const、解构赋值等）；

- wxs遵循CommonJS规范；

wxs代码可以编写在wxml文件中的`<wxs>`标签内，类似于js代码可以编写在html中的`<script>`标签内。每个`<wxs>`标签必须提供`module`属性，用来制定当前wxs的模块名称，方便在wxml中访问模块中的成员。
```xml
<view>{{m1.toUpper(username)}}</view>

<wxs module="m1">
  module.exports.toUpper = function(str) {
    return str.toUpperCase()
  }
</wxs>
```
还可以放在`wxs`文件中，类似于`js`文件，引入外联脚本时，须添加`module`和`src`（相对路径）属性：
```jsx
function toLower(str) {
    return str.toLowerCase()
}

module.exports = {
  toLower: toLower
}
```
```xml
<view>{{m2.toLower(username)}}</view>

<wxs src="../../utils/tools.wxs" module="m2"></wxs>
```
